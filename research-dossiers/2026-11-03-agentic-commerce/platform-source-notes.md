## Visa

- [Visa product announcement](https://investor.visa.com/news/news-details/2025/The-Future-is-Here-Visa-Announces-New-Era-of-Commerce-Featuring-AI/), 2025-04-30. Original body fetched (web tool turn18view0 / turn21view5, lines 58–69). Introduces Visa Intelligent Commerce and names collaborators including Anthropic, IBM, Microsoft, Mistral, OpenAI, Perplexity, Stripe and Samsung. Its language is explicitly prospective: agents using Visa credentials at accepting merchants is described as coming “Soon.” High confidence announcement; insufficient evidence here for universal launch or transaction adoption. Visa's 4.8 billion credentials and 150 million acceptance locations describe existing payment reach, not agent-enabled customers or successful agent checkouts.
- [Trusted Agent Protocol announcement](https://corporate.visa.com/en/sites/visa-perspectives/newsroom/visa-unveils-trusted-agent-protocol-for-ai-commerce.html), 2025-10-14. Original body fetched (turn18view2, lines 4–32). Protocol available that day in developer center/GitHub, developed with Cloudflare. Agent-specific signatures carry intent, consumer recognition and optional payment information. Built on HTTP Message Signatures and aligned with Web Bot Auth; initial specifications apply to Visa network in this phase. High confidence shipped specification; no transaction count or measured merchant acceptance rate. Its 4,700% retail traffic claim is attributed to Adobe and must not become a completed-purchase growth claim.

## Shopify: current interface differs materially from early Storefront MCP

- [Catalog interface documentation](https://shopify.dev/docs/agents/catalog), undated live docs accessed cutoff. Original body fetched (turn18view5, lines 78–103). Global Catalog spans Shopify merchants; Storefront Catalog scopes to one store. Both implement UCP Catalog. Documented endpoints are `https://catalog.shopify.com/api/ucp/mcp` and `https://{storeDomain}/api/ucp/mcp`; agent profile authentication, no API key. High confidence current documented architecture, medium confidence exact historical availability absent dated release.
- [Migration documentation](https://shopify.dev/docs/apps/build/storefront-mcp), original fetched (turn18view6, lines 117–158). Old `/api/mcp` catalog/cart tools are marked removed. UCP replacements include catalog, cart, checkout and ask-business functions; checkout requests require authentication or signatures. Customer Accounts MCP unchanged. A report teaching old Storefront MCP endpoint as current would be stale.
- [Dated cart deprecation](https://shopify.dev/changelog/posts/storefront-mcp-cart-tools-are-being-deprecated-in-favour-of-ucp-cart-mcp), 2026-06-24. Original body fetched (turn24view1). Old get/update cart maintained until August 31, 2026. New Cart MCP exposes create/get/update/cancel; update replaces full cart state. High confidence transition announced before cutoff. Documentation availability proves callable design, not successful real buyer conversions; no production API calls made in this research.

## MCP adoption: inventory is not invocation telemetry

[Official MCP Registry launch](https://blog.modelcontextprotocol.io/posts/2025-09-08-mcp-registry-preview/), 2025-09-08, original turn18view7. Defines registry as open catalog/API for publicly available servers, with maintainer self-reported information, downstream public/private registries, preview limitations. High confidence scope. A server listing measures published/discoverable inventory; it does not prove a working endpoint, unique active merchant, installed client, actual tool invocation, paid order, retention or revenue. This source supplies no invocation total. No defensible current numerical adoption estimate obtained; do not manufacture one from listings. Needed: deduplicated version/domain inventory plus operator/client telemetry with tool-call denominators, active tenants, successful outcomes and period.

## Cloudflare Web Bot Auth and signed agents

- [Web Bot Auth explanation](https://blog.cloudflare.com/web-bot-auth/), 2025-05-15, original turn13view2 / turn21view4 lines 830–846. HTTP message signatures and request mTLS introduced as proposals with closed beta. High confidence dated proposal/beta; not an IETF final standard.
- [Signed agents launch](https://blog.cloudflare.com/signed-agents/), 2025-08-28, original turn18view4 / turn26view0 lines 830–890. Recognizes user-directed agent infrastructure by cryptographically signed requests. First cohort ChatGPT agent, Goose, Browserbase, Anchor Browser; Radar displays observed traffic patterns. Directory/application and recognition available then; group firewall controls described as coming soon. High confidence classification shipped; exact current control availability unverified. Signatures identify origin/operator, not automatically human authorization, safe behavior, purchase intent accuracy, or permission from every site. Radar traffic is requests observed on Cloudflare, not global agents or completed orders.

## Decision implications and unresolved checks

Inference: identity, payment authorization, catalog discovery, cart/checkout semantics and buyer distribution are separate layers. A connector-only wedge faces native platform encroachment; a measurable failure/reconciliation layer may still matter, but demand must be demonstrated with merchant traces and paid design partners. No primary evidence here establishes a broad market for third-party connectors.

Remaining evidence gaps: network live transaction volume and liability allocation; current regional/merchant eligibility; agent checkout success by merchant; current Shopify global rate limits/commercial terms; merchant revenue attribution; agent traffic versus purchase conversion; independent security tests; current Instinct availability and measured fulfillment. Appropriate next test is consented merchant-level end-to-end traces and error taxonomy, not more protocol listing counts.
